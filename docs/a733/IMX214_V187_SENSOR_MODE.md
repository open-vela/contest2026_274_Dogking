## 当前状态

本版是**源码实现＋主机模拟回归＋AArch64 对象编译通过**，不是摄像头实拍通过。
没有绑定实机供电/MCLK/总线所有者、没有启动 CSI/D-PHY/DMA、没有注册 `/dev/video0`，
没有生成或烧录新镜像，也没有把 Linux ISP 当作已经移植到 openvela。

相对 v186 的实质新增：

1. TWI3 支持严格 ID 验证后的寄存器写事务，供传感器模式执行器调用。
2. 固定 1080p 模式包格式、完整性检查、逐项执行及 14 项关键寄存器回读。
3. 接收端未 armed 不开流；显式写 `0x0100=0` 停流并确认接收端 DMA 空闲。
4. 失败锁存、保留资源及拒绝自动重试；第一次错误和停止错误分别保留。
5. CSI RAW10-in-LE16 候选帧的 stride、容量、保护区、地址编码与越界检查。

这些部件仍需真实板级提供者连接，不存在通过 NSH 传入几个布尔值就越过电气门禁的入口。
芯片适配 skill 的供电/时钟/身份门禁仍保留，软件实现不代替实机验收。

## 固定参考与配置来源

只读参考 `../bsp-product-aiot-stable/drivers/vin/modules/sensor/imx214.c`，SHA256：
`e05a71fe4843c81d354ab9fa30bbd809796c21d557a87af54b550ba4e4a23832`。

本地 BSP 的 1080p 是裁切后 2×2 合并，线长5008、帧长2128、四通道 RAW10、
24MHz MCLK、标称800Mbps/lane；上游 IMX214 的1080p是另一套中心裁切配置。
两者不能只看分辨率相同就混用寄存器/PLL。BSP 的停流回调直接返回成功，
没有实施停流，因此本项目不能沿用它的“返回0即停止”语义。

`tools/export-a733-imx214-mode.py` 固定原文件摘要后提取配置，生成到私有 `out/`：

必须使用全新目录。输出保留完整参考源文件、GPL来源说明和生成记录；**没有把 GPL
模式表改成 Apache，也没有把它静态链接进固件**。衍生配置保留 GPL 来源状态，
尚未作为已审核的可分发固件资产发布；发行前另行处理许可要求。

`a7b2102ba05c51de1a8a7602152505f4feedbeb3ec9facdda70710f9639bb2af`。
导出时显式去掉表末 `0x0100=1`；按 IMX214 时钟寄存器定义另补 `0x0136/0x0137=0x1800`。
移除/补充操作都记录在 manifest，不静默修改原 Linux 文件。
厂商报告 Bayer 为 SBGGR10，但内存布局和实际色序仍需取帧确认，所以包内 Bayer 提示为
UNKNOWN，不直接让它绕过 v186 RAW 前处理的色序要求。

## 模式执行器的安全契约

`a733_imx214_mode.c/.h` 使用 A7CM v1 字节格式，不用直接映射的 C 结构解析二进制。
最多512条操作；CRC保护头部与数据，拒绝未知版本、尾部多余字节、非法操作及缺失字段。
CRC只防损坏，**不是认证**；实际提供者必须验证固定SHA256和来源，不能只信旁边可改的
manifest。离线检查器也锁定本版配置/参考的精确SHA256。

`prepare` 的顺序：

- 电气条件、独占权及配置来源限定均通过后，复制最多2096B脚本到内部快照再校验。
  I/O回调即使改写原输入，也不能把后续配置操作变成隐式开流。
- 严格读取 `0x0016 == 0x0214`，并确认传感器原本处于standby；已有视频流则拒绝接管。
- 逐项写配置。脚本不能写STREAM_ON、soft-reset或低地址身份区域。
- 回读方向、RAW位宽、lane、外部时钟声明、帧/线长、输出宽高及standby，共14项模式字段。
- 全流程5秒预算，单次寄存器回调30ms；延迟条目单次≤50ms、累计≤250ms。
  检查每次回调耗时、剩余总预算和实际延迟。回调自身也必须有界；不能用事后计时拦截
  卡死的物理总线访问。

`start` 必须先得到接收端“正确模式、私有DMA映射和缓冲已armed”的确认，才单独
写 `0x0100=1` 并回读。开流成功仍然**不等于收到了一帧**。
接收端只有完全未取得新资源/启动DMA时，才能用 `-EBUSY` 做无副作用拒绝。

`stop` 先写 `0x0100=0` 并回读，再等待接收端证明DMA/IRQ/回调空闲。
任一步失败或迟返回，`retain_resources` 保持为真，不能释放缓冲、关钟或开始下一轮。
同一失败停止不反复重试/复位；若显式清理成功，保留原错误而不是把它改写为成功。
配置包失去来源信任不能阻止已经运行的设备进行固定安全停流，但电气/独占条件仍需成立。

## TWI3 的扩展

原严格探测成功后才置 `identity_verified`；新增的读/写回调仍逐事务核对时钟、引脚和
总线空闲。写接口发出7-bit地址0x10对应的0x20写地址、BE16子地址、数据和有界STOP。
拒绝身份/OTP、soft-reset和非法stream值；失败使缓存身份失效，不能直接重复写。
没有增加PMIC、GPIO、PLL、CSI或NPU写操作，也不在开机时探测。

此版本仍只接受v186的窄 handoff 条件，不是已经完成冷启动供电/引脚/时钟提供者。
模式执行器与TWI3回调是可连接部件，**尚未绑定物理板级所有者和接收端**。

## CSI帧容量候选

`a733_csi_frame_plan.c/.h` 是无分配、无MMIO的算术模块。依据BSP RAW Bayer10内存
depth=16、line_length=width×2、16行分配对齐，以及dma140地址字段的`IOVA >> 2`事实：

| 1920×1080候选 | 字节/数值 |
| --- | ---: |
| stride | 3840 |
| 有效图像字节 | 4147200 |
| 保守分配行数 | 1088 |
| payload容量 | 4177920 |
| 前后各64B保护区后的总容量 | 4178048 |

有效图像、分配填充和保护区是不同概念，不能把保护区/额外行当成画面导出。
规划检查64B对齐、映射容量、加法溢出、34-bit寄存器可编码范围及完整末地址。
34-bit仅是此参考地址字段的编码能力，**不是实际CSI IOMMU映射或地址宽度已经验收**。
输入是CSI主机设备地址，不是CPU指针，更不能直接拿NPU master的映射复用。
本版没有分配实际DMA内存、修改全局预留区、创建映射或执行cache/IRQ操作。
RAW10实际装入LE16的位对齐、Bayer和stride仍要用真实帧/总线数据验证。
