# v210：语音路径修复与热启动延迟候选

v209 已保留：源代码/镜像/恢复目录均不覆盖，摄像头绑核及异步刷新暂缓板测。
v190 原始日志保存在 docs/evidence/voice-v190-board-20261029。
本版不是“全链路已通过”，目标是补齐可测部署、确认 A76 执行并减少热路径开销。

## 已知基线和证据边界

- v190 三条 general-wav 都报 -20，不能据此声称执行过通用 ASR。
  NuttX FAT 缺少中间目录也返回 ENOTDIR；标准录音原本单独打包，
  这是部署问题的有力线索，但旧日志不足以最终确认原因。
- v190 TTS 软件首包约 2.80 秒，其中 CPU 声学约 2.05 秒。
  该日志没有成功的通用 ASR、LLM、多轮闭环或真实声学首音测量。
- 3–5 秒是“说完话→首段有效回复音频”的热启动目标，尚未测得。
  冷启动模型加载、首次会话初始化必须单列，不能藏进预热而声称冷启动达标。

## 本版改动

1. 标准镜像加入三条锁定测试 WAV；general-wav 打印输入/格式/后端阶段。
   缺文件时在 NPU 执行前停止，不创建假输入，不吞掉错误。
2. ASR 每个接收批次、flush、reset 使用 CPU6；CPU 声学使用 CPU7，
   vocoder 调用使用 CPU6。每次改变约束都经阻塞调度和两次实际
   MIDR/MPIDR 确认；失败有界返回并恢复原亲和性。仅改变当前工作线程，
   不改变全局调度、CPU 频率、其他服务或 DMA/NPU 执行规则。
3. 语音 Tensor CRC 复用 v209 经运行时 ISA/实际核心核验的 ARM IEEE CRC，
   保留完整软件回退、独立 legacy 分支和所有 Tensor 检查。
4. Joiner 有限值校验与 argmax 合并一次完整扫描；仍检查全部 6254 项，
   tie 顺序和遇到任何非有限值的失败行为不变。
5. LLM 常驻池每矩阵检查实际核心与 mask；正确时不反复设置亲和性。
   定点/浮点计算、权重、行划分、归约顺序不变。
6. 真正由 LLM 生成的首个短语更早交给 CPU 声学合成；
   首短语逗号门槛 3 字、软门槛 8 字，后续仍 6/32。
   软门槛保留一个码点前瞻，标点跟随前句，剩余文本完整播放。
   没有固定回复、空音频、丢弃后半句或旁路 ASR。
7. 增加 ASR 批次累计和最终 flush 时间；它们包含嵌套 NPU 耗时，
   不可相加成总延迟，也不代表麦克风真正的结束说话时刻。
   close 时的 accept/flush 是最后一轮，三模型调用计数是会话累计；
   多轮分析应优先使用每轮 voice-stage 的绝对单调时间戳。

## 不变项与风险

通用 Zipformer 是 36 输入/36 输出、35 路跨块状态，不复用旧关键词模型。
声学仍为 CPU Matcha，vocoder 为 NPU；不是“全部 TTS 都跑 NPU”。
模型、许可证、导出包、量化、内存池/保留区、硬件提交/IRQ/MMU 不变。
不自动录音、启动摄像头、联网或执行 MCU 动作；原来的取消、所有权、
join 失败保留至重启策略继续有效。较短首句的语调和连续播放需板测。

完整构建、封存、镜像哈希及测试命令见随后生成的 release/test 文档。
