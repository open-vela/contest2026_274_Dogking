# v211：减少可证明的语音热路径重复工作

保留v210镜像、源码标签及r6恢复归档，模型/内存池/硬件ABI/时钟/精度不变。
仍为NPU Zipformer → CPU MiniCPM5 → CPU Matcha → NPU vocoder → I2S。
没有新板测数据，3–5秒仍是待测目标，不使用主机耗时冒充A733收益。

## 改动和代价

- ASR：在原有35状态反馈及完整输出校验之上，将16k PCM合并为40ms批次。
  小回调仍逐次检查取消/错误/8秒上限，结束时排空不足40ms尾巴。
  不丢样本，最多给进行中的识别调度增加约30ms等待；理想10ms输入时，
  每秒绑核确认次数由100降为25。大输入不会被强迫等待真实时间。
- ASR收尾：只生成最后一个真实frame窗口所需的波形零尾，不再继续生成
  已不会送入encoder的特征；仍调用frontend/decoder finish，不能用零mel替代。
- LLM：g_model_lock保护下复用最多256KiB的Q8工作内存，不缓存量化结果。
  每次仍执行原量化/行划分/点积/归约，超大输入沿用原临时分配。
  GGML零块捷径不一定写bsums，因此量化前显式清零请求范围，避免复用残留；
  不改变权重、量化方法或模型。池全部join成功后unload才清零释放。
- TTS：engine mutex内复用mel/wave/PCM，共371200字节，关闭时清零。
  全部wave浮点仍检查、全部文本仍验证、完整尾句仍播放，不跨引擎共享。
- 播放：首次门槛从100ms真实PCM降为40ms，补缓冲仍100ms。
  这是PCM量，不保证墙钟节省60ms；不生成空白/填充音频，不忽略设备错误。
