# 桌宠 Vela 五分钟产品讲解与分段拍摄稿

日期：2026-11-04。按指定的16个模块排列，成片目标5分钟。旁白按正常语速录制，段落可分别重拍；命令输入、启动和模型加载另录完整素材，再用旁白覆盖或标注加速。实际连续交互镜头保留真实速度，不用跳剪制造延迟数据。

配套操作见 [完整演示命令](VIDEO_DEMO_COMMANDS_20261104.md)。旁白中的历史数据可用已保存的日志配图，不能贴到本次画面上冒充新测试结果。v229为修复候选，尚待多轮板测；正式录制优先使用已经现场确认能工作的版本。

## 01 启动 SMP 与 4 GiB 内存适配

**成片时间：00:00–00:18，18秒。**

**旁白：**

大家好，这是我的桌宠 Vela。它的核心不是外壳，而是把 openvela 原生运行在 A733 主控上。我完成了八核启动、SMP 和四 GiB 内存适配，为语音、视觉和模型常驻提供系统基础。

**画面：** 桌宠正面2秒→开发板上电→启动日志→`ps` 的八个CPU空闲任务和 `free`。启动等待用明确标注的加速镜头，不必全程占用旁白时间。

**照片：** `桌宠正面.jpg`、`桌宠内部.jpg`。字幕：`原生 openvela/NuttX｜6×A55＋2×A76｜4 GiB`。不要说4 GiB全部都是当前空闲内存。

## 02 Wi-Fi 从 USB 固件到可用网络

**成片时间：00:18–00:34，16秒。**

**旁白：**

网络部分，我适配了板载无线模块的 USB 枚举、固件加载、WPA2 连接和 DHCP，并接通 NTP 校时。设备不仅能扫描热点，还能获得可用网络，为在线对话和远程维护提供基础。

**画面：** 无线模块特写→`wifi scan`→`ifconfig`→ping→时间状态。连接密码、API密钥及其他私人信息不要入镜。

## 03 SSH FTP 与系统运维工具

**成片时间：00:34–00:48，14秒。**

**旁白：**

我还接入了 SSH、FTP 和系统状态工具。开发时可以远程进入终端，传输模型、录音和日志，不必每次拔卡重刷；配置与运行状态分开管理，也便于现场定位问题。

**画面：** 电脑SSH终端与串口同时入镜，展示状态查询和一个录音文件的FTP下载。FTP只用于可信局域网，不把它描述成加密传输。

## 04 BLE 官方 Host 接入与共存验证

**成片时间：00:48–01:02，14秒。**

**旁白：**

蓝牙方面，我把控制器接入 openvela 官方 Host，完成启停与扫描。历史五轮测试记录了一千五百零一条广播结果，同时维持 SSH 和四十七次成功 ping，为后续家居节点通信打下基础。

**画面：** `bttool` 扫描结果、停止回调、`Scan state=idle`；旁边叠加历史数据卡片。字幕标明 `v145 历史短测`、`1501条记录，非1501台设备`。不说ESP32-S3双板GATT业务已闭环。

## 05 SD UFS 与模型存储管理

**成片时间：01:02–01:19，17秒。**

**旁白：**

存储采用 SD 启动、UFS 管理模型资产的方案，提供挂载、复制进度和文件校验。模型完整加载到内存后，热请求复用常驻权重，避免每轮反复读取大文件。

**画面：** UFS芯片/板背特写→`ufs status`→`/ufs/models` 的完整模型文件→LLM缓存命中日志。字幕：`存储加载与热推理分别计时`。不宣称UFS已实现1000 MB/s。

## 06 I2S 录放音与应用 PCM 接口

**成片时间：01:19–01:38，19秒。**

**旁白：**

音频使用 ICS43434 数字麦克风和 MAX98357 功放。我完成 I2S 采集、PCM 转换、重采样和扬声器播放，并加入麦克风增益与播放音量控制。应用可以直接录音、回放，也能使用连续音频接口。

**画面：** 合并模块特写→录制一句话→原声回放→音量调整。建议录音内容：“这是 openvela 上的 I2S 录放音测试。”不要让旁白盖住实际回放。

## 07 VIP2 NPU 运行时与正确性验证

**成片时间：01:38–01:57，19秒。**

**旁白：**

NPU 部分，我实现了内存映射、缓存同步、任务提交和输出校验，并与 Linux 厂商运行库的参考结果对照。验证不只看中断成功，还包括全部张量、动态输入，以及 YOLO 六路输出的一致性。

**画面：** `npu info`、`npu selftest`→黄金输出校验日志→简洁链路图。明确 Linux 用于参考验证，实际产品在 openvela 上执行；不把selftest等同于全部模型验收。

## 08 通用 ASR 真实语音到转写文本

**成片时间：01:57–02:14，17秒。**

**旁白：**

通用语音识别采用 Zipformer，模型部分由 NPU 执行，CPU 负责特征和解码状态。我还处理了跨块缓存、开头音频保留与静音端点，让自然语音能够变成完整的请求文本。

**画面：** 用户说“请介绍一下你的功能”→MIC状态→实际转写文本。保留真实识别结果，不预先把正确答案写在终端冒充输出；不展示无依据的准确率百分比。

## 09 本地 LLM MiniCPM5 与低延迟策略

**成片时间：02:14–02:32，18秒。**

**旁白：**

本地语言模型使用约六百八十八 MB 的 MiniCPM5 一 B 量化模型，在 CPU 上推理。通过权重常驻、前缀缓存、多核计算和工作区复用降低开销，并让用户在响应速度与有限上下文之间选择。

**画面：** 模型文件大小→加载完成→热请求 `cache-hit`→短句逐字输出。冷加载与热请求分开标记，不把文本首字等同于扬声器首音。

## 10 本地 TTS CPU 声学与 NPU vocoder

**成片时间：02:32–02:50，18秒。**

**旁白：**

本地语音合成采用 CPU 声学模型加 NPU vocoder，再经 I2S 输出。我重点修正了短语边界、末句和尾包处理，让回复更完整，并通过队列衔接生成与播放。

**画面：** 文本命令→CPU声学/NPU vocoder日志→播放“你好，我是桌宠 Vela，很高兴认识你。”保留2–3秒实际声音。不要说整套TTS都在NPU，也不把英文拼读称为自然中英混读。

## 11 常驻语音服务与自动多轮

**成片时间：02:50–03:08，18秒。**

**旁白：**

在应用层，我把单次测试升级为常驻语音服务：准备一次，空闲持续监听，完成回答后自动进入下一轮。用户不用每句话都输入命令，系统也能明确显示监听、处理、播报和停止状态。

**画面：** 一次 `aipet run`→第一轮完成→再次 `READY MIC ON`→第二轮。字幕：`半双工：播放结束后恢复监听`。不要在播报时演示“语音打断”，当前没有全双工/AEC/唤醒词。

## 12 端云两条链路与用户选择

**成片时间：03:08–03:26，18秒。**

产品提供完整的本地和联网语音链路。离线时，识别、对话和合成都在设备侧完成；联网时，可以组合讯飞语音和 DeepSeek 等服务。用户明确选择模式，强制联网不会偷偷切成本地。

## 13 MIPI 摄像头 Radxa 13M 214 适配

**成片时间：03:26–03:44，18秒。**

视觉输入使用瑞莎十三 M 二一四摄像头。我从电源、时钟、传感器通信和模式配置，推进到 MIPI、CSI 与 RAW 采集，并修正偏黑、颜色异常和重复采集问题，得到可供应用处理的当前画面。

## 14 摄像头 YOLO SPI 识物与视觉链路优化

**成片时间：03:44–04:10，26秒。**

**旁白：**

采集画面经过预处理后送入 NPU YOLO，检测框与底图按同一帧显示到 SPI 屏幕，并能播报物体名称。通过减少重复准备、优化 CRC 与输出扫描，历史稳态帧率从二点四八三提高到七点七三三 FPS，三十秒完成二百三十一次推理。

**画面：** 摄像头对准杯子或手机→屏幕上的实际检测框→移动物体→历史性能图。只按真实检测类别播报；COCO类别不覆盖所有物体。

**数据字幕：** `2026-10-29 历史短测｜v206 2.483 → v208-r2 7.733 FPS（稳态）`；`v208-r2：30s，231帧/231次推理，整体7.324 FPS`。不把17ms硬件段换算为整链60FPS；这组历史数据也不能归功于当时尚未生效的A76和硬件CRC。30FPS及长时稳定尚未验收。

## 拍摄执行与素材清单

- 先把16段旁白分别录好，每段开头留1秒安静，结尾留2秒，便于剪辑。整段讲话尽量自然，不要逐个念寄存器名。
- 设备实拍固定机位、固定灯光，避免屏幕反光。屏幕可拍斜侧小角度，并调整曝光以看清画面和检测框。
- 系统证据用屏幕录制，终端字号放大；设备动作和真实声音用相机同步录。开拍前拍手一次便于对齐音轨。
- 所有密码、API Key、APISecret、签名URL和私人聊天内容不入镜。首次配置提前完成，正式画面只展示就绪状态。
- 每个模块至少保留：全景1条、操作过程1条、结果特写1条、无操作静态照片1张。启动、模型准备、30秒视觉测试录完整原素材。
- 正式成片围绕openvela的系统与应用成果；配套电路板和整机照片用于说明工程落地，不取代软件证据。
- 旧PPT中的两处文案按新版修正：强制cloud不回退本地；v227起桌宠UI/语音步数×20，不再讲×10。
