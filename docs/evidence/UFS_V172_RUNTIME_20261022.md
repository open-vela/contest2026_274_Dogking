## 末尾dd错误：已定位到NSH的64位返回值截断

`dd ... bs=4096 skip=31256496 count=16` 报 `skip lseek failed: 2`。
实际offset=128026607616，赋给32位int后变为-822411264，因此被误判失败；errno=2
是旧值，不是UFS返回的错误。v172实际ELF在lseek后检查的是w0的符号位。
SDK `apps/nshlib/nsh_ddcmd.c` 四处把 `off_t lseek()` 返回值保存到int；BCH/VFS
的off_t没有这个问题。v173补丁直接检查off_t返回值，不再经过int。

主机回归使用实际NSH函数体和稀疏普通文件复现旧错误，并验证修复后2GiB、4GiB、
128GB偏移skip/seek/verify，以及真实seek失败；不接触物理块设备。

这是一次受控窗口的写入/正常flush/还原通过，不等于FAT挂载、模型文件、突然断电
一致性、长期稳定性或独立PMIC/M-PHY冷启动通过。v173的数据文件系统仍需新板测。
