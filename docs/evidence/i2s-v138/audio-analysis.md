# v138 实机矩阵录音分析（2026-10-11）

来源：用户本轮粘贴的启动/八组命令日志，以及工作区 `音频测试文件/` 中的八份 WAV。
原始录音只读，未修改或覆盖；各文件 SHA-256 见 `audio-analysis.json/csv`。
原始日志保存为 `board-matrix.log`。分析使用实际 PCM 数值和频谱，未执行主观试听或 ASR。

## 结论与已证明的边界

本轮未获得有效语音证据，v138 录音状态为 **audio-content-failed**。
用户提供的启动日志已进入 NSH，八组操作均完成；不能据此扩大为多次冷启动或长稳通过。

八份 WAV 都是 48 kHz、mono、S16、144000 样本、3 秒、288044 字节。
日志各组 elapsed=3100 ms、warmup=4800、target/consumed RX=148800、hw RX=148801、
FIFO peak=1、timeouts=0、status=0、committed=1。
各组 FMT0、RXMAP3、PB8 pull 回读与命令一致；WAV 的 min/max、平方和、非零数、
零数、符号跳变与日志逐项精确匹配。因此文件对应关系和传输计数成立，不能视为
输入内容通过，也不能单凭 RXCNT 前进证明每个映射源寄存器都在更新。

三段各 1 秒的 RMS 差别都小于 0.4%，100 ms 窗口也没有强烈的能量起伏。
主谱峰为约 6.28..8.14 kHz，300..3400 Hz 能量占比仅约 9.4..12.7%；
原始 FIFO 低字节 55/aa 合计约占 15%。这些特征延续先前强干扰/时钟型图案，

## 修正此前半帧结论

此前“right 无声、left 电流声，因此已排除半帧配置问题”的推断过强。
现在只能确认控制位与 RX map 改变、两种映射输出不同；右侧恒值尚不能证明
slot 1 接收源在按真实 PB8 数据更新，也不能直接当作未选半帧高阻的物理证据。

代码审计发现 CHCFG=`00000001`，即 RX_SLOT_NUM=0；同时右侧 RXCHMAP3=1。
厂商 BSP `snd_sunxi_i2s.h:148..172` 定义 RX_SLOT_NUM 位于 CHCFG bits7:4，
`snd_sunxi_i2s.c:230..234` 用 channels-1 同时设置 RX_SLOT_NUM 和 RX_CHSEL。
当前仅一个 RX 配置槽却映射 slot 1 的配套行为是一个**待核验的软件疑点**。
仅凭这些源码不能断定它就是右侧恒值根因，也不能断定改成两个 FIFO 声道会修复。
本轮不修改已验证的 FIFO 节拍、录制时长、PCM 位移，不生成无新证据的 v139。

## 下一步硬件定位

1. 断电后确认模块 SD 到 PB8/物理 pin38 的通断，核对 PB7/pin40 与 PB8/pin38
   是否接反、模块丝印与实际引脚、L/R 是否确实接 GND。
2. 通电测麦克风端 VDD/GND，并检查 CHIPEN（若引出）为高。
3. 在 `capturecfg=0,0,2,3000` 活动采集期间，逻辑分析仪/示波器同时检查 PB5/SCK、
   PB6/WS、模块 SD 端和板侧 PB8。目标约 3.072 MHz/48 kHz；先观察超过 100 ms
   warmup 后的数据，按标准 I2S、24-bit、32-bit slot、一位延迟解码。
4. 若模块端 SD 有声学变化而 PB8 没有，优先处理接线/接触；若两端 SD 都没有有效
   输出，检查供电/CHIPEN/L/R、去耦和模块，必要时换一个已知可用的 INMP441。
   若 PB8 已有干净且随声音变化的数字数据，再回到 RX slot 数/映射与输入时序审计。

[INMP441 官方数据手册](https://invensense.tdk.com/wp-content/uploads/2015/02/INMP441.pdf)
规定 L/R 选择输出半帧、非驱动时间 SD 三态、标准 24-bit I2S，并给出近端 0.1 µF
去耦及约 100 kΩ 外部 SD 下拉的参考连接。内部 PB8 pull-down 不等价于已验证的
外部电路，也不能替代实测波形。

## 复现

```text
python tools/analyze-inmp441-matrix.py --audio-dir ../../音频测试文件 --board-log docs/evidence/i2s-v138/board-matrix.log --output-dir docs/evidence/i2s-v138
```

需要 NumPy。谱统计对数据去均值后使用 4096 点 Hann 窗、50% 重叠的功率累计。
生成 JSON（含各文件哈希、分秒/100 ms 数据、原始日志核对）与 CSV。
