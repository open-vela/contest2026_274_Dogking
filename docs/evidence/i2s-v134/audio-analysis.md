# v134 INMP441 PCM 修复证据

> 2026-10-11 实机否决：本页原先依据 v133 原始字节布局提出的 `>> 8`
> 转换并未修复输入。三段 5 秒录音都成为幅度接近满量程、统计特征近似的
> 稳态电流声；安静、说话、拍手的 RMS 分别约为 21097、21111、21176。
> 因此 v134 只能证明文件写入和 RX FIFO 活动，不能作为 INMP441 音频通过
> 证据。后续改用官方 Linux `S24_LE/S32_LE` 的 32-bit resolution 单声道路径。

## v133 三段 WAV 离线分析

用户分别采集了 5 秒安静、说话和拍手录音。三份文件均为 48 kHz、单声道、
16-bit、240000 帧，文件大小 `480044` 字节；大小相同是固定时长的正确结果，
不能用于判断内容是否相同。三份 PCM 的 SHA-256 不同，但统计如下：

| 文件 | min/max | RMS | 十等分 RMS 范围 |
|---|---:|---:|---:|
| silence | -109/119 | 82.437 | 81.86..83.25 |
| voice | -125/115 | 82.729 | 82.15..83.30 |
| clap | -123/119 | 82.588 | 82.23..83.06 |

拍手没有瞬态峰值，说话也没有能量包络变化；三者试听均为电流噪声。因此 v133
只证明时钟、PB8、FIFO 和文件写入工作，不能证明有效声音采集。

## 根因

厂商 Linux I2S 驱动对 `S24_3LE` 使用 sample resolution 24 和 `RXOM=1`。
A733 RX FIFO 返回的原始字形如 `ffa66b34`、`00355595`，有效有符号样本位于
bits 23:0，最高字节是符号扩展。v133 使用：

```c
(int16_t)((int32_t)raw >> 16)
```

这只保留了约 8 位有效信号。v134 改为：

```c
(int16_t)((int32_t)raw >> 8)
```

即丢弃 24-bit 样本的最低 8 位，得到完整的 16-bit PCM。

## 实机验收门槛

刷写 v134 后分别录制安静、说话和拍手。`capture_min/max` 应显著超出 v133 的
约 ±120，并且说话/拍手 WAV 的峰值与时间包络必须明显区别于安静录音。最终以
实际可辨识的回放内容为通过标准，不能只依据 `nonzero` 计数。
