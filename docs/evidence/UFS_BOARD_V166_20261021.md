# UFS v166 软件/镜像验证记录（2026-10-21）

## 功能范围

板级 CCU/RTC取证、生产HCI拒绝门禁、旧hwdiag旁路修复。不是cold-start或UFS高速存储完成。
没有连接开发板、执行SMC、访问真实PMIC/UFS、刷写、格式化、迁移或修改原Linux开发目录。
实际板号/焊接/供电/枚举/DMA映射/吞吐/长稳仍未验收。

## 主机与对象验证

- `out/test-ufs-board-v166-r1.log`：原生产board模块，ASan/UBSan、Werror；
  52次错误返回注入+13次第二遍数据变化，选择器、计数饱和、短报告缓冲区及空参数通过。
  只有固定13个CCU/RTC地址可被调用。实际HCI允许函数无条件false，即使gate均开。
- `out/test-ufs-transport-v166-r1.log`：14场景，包括board命令、生产拒绝策略对应负例、
  不分配DMA/不读HCI/无写寄存器、无force命令。历史transport正向用host-only许可shim；
  真实生产拒绝函数另行链接/断言，**不是把真实MMIO授权做成可用入口**。
- `out/test-ufs-link-v166-r1.log`：保留v165生产link core，3357+577=3934故障点通过；
  临时SDK副本34项源码校验，篡改新增board源/头及hwdiag也会被拒绝。
- `out/test-ufs-collector-v166.log`：Linux只读取证工具9组通过。
- `out/test-ics-v166.log`、`out/test-playback-v166.log`：既有录音、x5、播放、
  PB7录音/空闲静音、错误退出和重复播放回归通过；本轮不改变音频源码。
- `out/test-checkpoint-v166.log`：恢复工具3组通过。
- `out/ufs-v166-arm-objects-r2/summary.json`：真实ARM64编译，源码/头hash与命令记录；
  UFS224B、board208B、link112B、hwdiag3392B、板初始化64B最大静态栈。
- `out/v166-board-object-imports.txt`：board对象仅引用memset/snprintf，没有SMC/PMIC写函数。
  MMIO读取经注入的固定allowlist回调；对象未定义导入少不等于没有该读回调。
- `out/v166-hci-gate-disassembly.txt`：ARM64生产门禁实际为`mov w0,0; ret`。
- `out/v166-source-invariants.json`：与v164共同29项critical中26项字节相同；
  3项变化是UFS驱动、CMake、Kconfig。另将新增link/board模块和旧hwdiag纳入当前34项。
  这不是全仓库逐文件不变声明；hwdiag改动有明确记录，历史输入本来未纳入29项。
- 原生Windows Git diff whitespace检查通过。WSL Git全仓检查因autocrlf视图产生大量
  CRLF误差输出，未用它改写/归一化用户文件，也不声称该次WSL检查通过。

ARM对象r1/r2的不同输出路径可影响debug/object hash；源hash和实际编译参数各自记录，
没有用对象hash差异代替源码差异。早先v165所有中间日志不覆盖、不删除。
