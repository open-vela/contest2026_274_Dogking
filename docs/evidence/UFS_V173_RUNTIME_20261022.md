## 本地源码检查的事实与尚未证明的推断

SDK v173 CONFIG_NSH_FILEIOSIZE=1024，普通NSH cp每次1KiB；cmp缓冲128B。
FAT对部分4KiB扇区有缓存，不能把每个1KiB syscall说成必然一条介质写。
但实际块写回调执行64KiB以内逐段精确回读及CACHE10，小块工作流不能发挥批量吞吐。
首次格式化约9.0405秒、1934写/1935flush，证明保守策略有明显附加开销，不证明长cp
具体停在哪一层。NSH cp原循环也缺少write返回0的退出路径；这是查到的代码风险，
**尚无证据证明本次实际触发**。本轮新utility对write0直接EIO，不修改旧cp实现。

v171短8MiB约67.3MiB/s不能当持续大文件速度；两遍16MiB/934ms带CRC，亦非纯介质测速。
模型loader现有256KiB fread无需另改RAM驻留逻辑。本轮优先修复复制/比较/可观测性，
不盲改PHY、不移除写后校验和flush。没有验证官方FAT的fsync→BIOC_FLUSH契约前，
不能仅为提速关闭介质持久化操作。

新方案、命令、风险见 [v174](../a733/UFS_BULK_V174.md)。原v173镜像/源码/文档不覆盖。
