# UFS v164 第一阶段开发证据（2026-10-20）

## 范围

用户新焊接128GB UFS3.1，希望模型/高频数据高速存取；明确以后统一板测并保留恢复性。
当前无芯片完整型号、实测rail、Linux枚举/冷启动波形。本轮没有SSH、录音、板上NPU调用、
烧录、块设备写入、格式化或数据迁移。**UFS 全功能适配尚未完成。**

## 已执行检查

- `tools/test-a733-ufs.py`：最终13个真实源码主机模拟场景，ASan/UBSan、`-Wall -Wextra -Werror`。
  启动不读写HCI、gated时拒绝HCI、inactive/busy拒绝接管、timeout/fatal/OCS/tag/status/residual/
  不支持块长隔离、正常64KiB分段/容量/边界、命令白名单（全部256opcode）、错误参数拒绝。
  另验证CAP64已置位但分配在4GiB以上/跨4GiB时，也必须在任何DMA提交之前拒绝并释放。
  DMA mock不是芯片一致性或真实UFS通过。初版12场景日志及初版源码归档仍保留。
- `tools/test-ufs-linux-collector.py`：4组，sysfs UFS controller身份、非UFS/partition拒绝、
  默认无raw读取、不可覆盖新报告/归档SHA、显式direct-read仅O_RDONLY、短读停止无重试。
- ARM64真实编译参数：最终`out/ufs-v164-arm-objects-r3/summary.json`；UFS静态最大224B、board64B，
  Werror通过。原`out/ufs-v164-arm-objects/board.log`保留首次检查命中旧SDK头声明问题；
  修复的是独立检查工具的overlay include优先级，未改SDK永久文件。
  r2对象为收紧DMA边界前的检查记录，不删除、不冒充最终源码。
- ICS43434、playback、I2S matrix、Agent音频边界、fbank、tensor及CRC主机回归已执行，
  日志 `out/test-v164-*.log`。保留v162生产音频源码hash和x5默认不变。
- `git -c core.autocrlf=false diff --check`通过；不把这个选项用于恢复目录status等价比较。

## 未通过/未实现

- 真实芯片电气/容量/介质读/写/速度/断电/长稳：未测。
- 冷启动PMIC/时钟/M-PHY校准/UIC/device-init：未实现。
- SoC UFS DMA aperture/SMMU bypass及安全固件handoff：未证明；CPU平坦映射/CAP64不能替代。
  当前统一板测只先登记/probe，不因HCS ready就直接提交DMA；timeout后需冷断电恢复。
- GPT分区与真实文件系统挂载、写缓存flush/写回读、模型迁移：未实现。
- 当前仅固件已初始化active-idle链路的显式只读接管，SD启动后不保证具备前置条件。
- 不继承Linux对某芯片的通过结论；不把官方产品规格当作本板协商结果。

完整边界、Linux脚本及后续步骤见[UFS存储说明](../a733/UFS_STORAGE.md)。
