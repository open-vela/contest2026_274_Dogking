# YOLO：端到端帧率而非只看NPU

链路：IMX214/MIPI RAW → CPU Bayer/色调/letterbox → 640×640 RGB → VIP2 YOLOv8n → 六输出解码/NMS → SPI同帧底图与框。CPU、NPU、SPI和采集分别计时，模型不变时先优化大的CPU重复工作。

## 优先级

1. **驻留和准备拆分**：模型、固定命令/模板和可复用缓冲驻留；区分不可变权重、命令、可变LOAD和输入。不变性要由唯一写者/租约证明，不靠猜测“上轮应该没改”。
2. **CRC与输出扫描**：保留全部六路输出、变化计数、权重正确性和检测结果检查。等价查表/slicing或合并遍历优先；硬件CRC的多项式、初值、反射、终值、字节序、短尾/不对齐都要与基线逐字节一致，不能误用CRC32C。
3. **像素与刷新**：缓存几何映射、合并能证明等价的像素工作，保留四种Bayer/YUV配置和letterbox坐标测试；只省无效/重复屏幕刷新，不让零检测残留旧框。
4. **局部调度**：确认工作线程真正迁移后再测试A76/硬件指令。配置成功但实际A55时按A55报告，不能把这次收益归因未生效优化。
5. **流水线**：从两槽开始，明确RAW/RGB/NPU/LVGL生命周期。生产者不能覆盖INFER/DISPLAY槽，消费者只接受相同frame_id；唯一显示线程调用LVGL。停止后等待DMA/推理/显示静止，失败隔离，不能强制复用未知所有权内存。

省重复清零必须证明后续完整覆盖目标范围，连padding/尾部也覆盖；部分有效输入不得继承旧frame。省重复权重扫描必须证明租约中不变，并保留硬件运行后的所需验证；不能因为CRC耗时就删掉正确性门禁。

## 正确性与性能一起验证

同输入legacy/cold/warm比较六路CRC、输出长度和最终检测；动态输入验证不是固定golden回放。空图应零检测并清框，新画面不能配上旧框。故障注入覆盖短frame、陈旧序号、队列满、取消、DMA/IRQ超时、显示失败和清理错误。

切勿通过降低输入尺寸、跳帧、少扫描输出/少校验、换模型或只测预览而仍沿用“每帧YOLO”标签。若用户接受这些取舍，作为不同模式单独报告。

## 历史板测口径

| 模式 | 30秒显示/推理 | 稳态FPS |
| --- | ---: | ---: |
| v206每帧YOLO | 74/74 | 2.483 |
| v207串行 | 154/154 | 5.158 |
| v208-r2串行 | 193/193 | 6.455 |
| v208-r2双槽 | 231/231 | 7.733 |

双槽整段含首尾为7.324FPS；额外生产而未消费的一帧不计。2.483→7.733约3.11倍是历史整链收益，不是NPU硬件提速3.11倍。实际该轮仍A55与portable CRC。

v206→v207：准备97.15→33.2ms，输出/权重检查152.4→55.2ms，硬件+等待约17.1ms基本不变。package 73.11→21.4ms是准备中的包含项，不再加一次。30FPS只是目标，不是已有结果。

基线证据路径见 [measurement.md](measurement.md)。复测需同场景、同配置、实际每帧推理及足够长窗口；不要把不同版本/输入的分段均值相加构造不存在的完整帧时间。
