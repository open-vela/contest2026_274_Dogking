# CPU LLM：首字、上下文与质量

先记录模型架构/GGUF hash、量化格式、prompt/reused/fresh/generated token、加载/预填充/首字/后续生成与实际核心。MiniCPM5-1B Q4_K_M在本项目运行于CPU，688065920字节，不能称为NPU LLM。

## 先消除冷加载与重复工作

- UFS主要影响模型读取；权重驻RAM后，不应继续把算力瓶颈归因SD/UFS。分别测文件读取与纯RAM推理，不能凭UFS3.1标签保证1000MB/s。
- 检查UFS已挂载、模型路径/文件大小正确，空文件与错误fallback先解决，再做prefill优化。预加载日志显示路径、字节和耗时，不输出密钥。
- 模型、tensor目录、线程池、可控工作区常驻；重用工作区仍需执行原量化/点积/归约并保持清零语义。例如GGML零块捷径不一定覆写bsums，不能把旧块残留带入新请求。
- unload必须等计算池停止且join完成；错误未静止时保留/隔离资源，不能为了“释放内存”强删仍在计算的任务。

## 预填充与KV

将预填充与逐token生成分开测。批量/层级预填充提高吞吐不一定降低极短提示的首字；固定同输入做batch1/4等候选比较，最后prompt token和LM-head的串行部分不能漏计。

精确token-prefix KV只复用完全一致的已评估前缀，并校验模型、配置和序列状态；不能跨用户/变更人设复用错误前缀。清除对话历史不必冷清固定人设KV，显式clear/unload语义要清楚。

本地历史默认0是v220起的产品取舍：降低新增prefill，但失去跨轮记忆；保留人设和可选有限历史，不擅自关闭云端历史。历史只提交完整成功轮；失败或截断回复不得污染下轮。

项目v219历史样本：83 prompt token首字3.797s，185 token首字24.672s；输入、历史与精确命中不同，不是控制变量实验，不能由此计算普遍的“关历史加速倍数”。

## 核心、数学与质量

- 工作线程内确认实际CPU迁移，再评价A76收益；记录亲和性、线程数量与真实频率。局部线程优先级/绑核，不改全系统FIFO策略或让音频任务饥饿。
- 量化/向量化与拆分矩阵行时核对布局、尾部、零块、累加类型；独立参考实现比较logits、冷/热、batch、缓存和生成结果。不能只检查输出看起来像中文。
- 模型/精度变更另做能力、指令遵循、情绪回复与幻觉检查；不通过过小max_tokens、隐藏EOS错误或裁剪末句来制造快首音。
- 面向TTS的首句可以比整条回复早交付，但只发送完整短语，保留完整末句，报告“首字”和“首句可合成”两个时间。动作等副作用只在完整解析、授权/边界验证后执行，部分生成文本不能触发动作。

## 建议的对照方式

先在停止常驻服务后查看 `aipet local status`；需要时只预加载一次。固定history/batch/core设置，比较冷/热、相同与不同问题。不要每轮clear、卸载、重启，再拿冷预填充结论否定常驻方案；也不能只重复同一句问答利用最长KV命中。

日志需记录完整提示长度与响应是否自然结束、上下文是否被正确提交。最终通过至少10轮不同短问、长回复、情绪场景、停止恢复和音频联动；TTFT提升不能以失去完整回答为代价。
