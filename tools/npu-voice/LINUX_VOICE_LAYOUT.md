## 本轮已经开发的 openvela 代码

- 可选 `CONFIG_A733_NPU_TENSOR_IO`，默认关闭，不改变通过固件的启动行为。
- 独立A7TV格式和两个新ioctl，最多64路输入/输出、128个区域，支持带偏移切片，
  使用原24MiB prepared池、16窗口MMU映射器，不扩大/更换全局DMA内存布局。
- 驱动自有缓冲区句柄、同fd所有权、大小/重叠检查、全量输出RAM传输，
  完成全部硬件/guard/CRC校验后才提交输出；失败时应用输出保持不变。
- 硬件/guard错误隔离后续提交，不自动重试/重启；恢复失败时保留映射和 backing 内存，
  防止仍可能在途的DMA访问已释放/复用内存。必须冷重启后继续检查。
- 公共 `system/a733_tensor_client.h` 客户端。产品应用不包含NuttX私有头或访问诊断节点。
- 24组主机/驱动模拟/公共客户端测试，ASan/UBSan，包含真实39路303684/299524字节长度；真实NuttX编译器已分别编译
  新旧驱动分支、解析器、客户端和KWS C核心。**仅目标对象检查，未链接/刷入新固件。**
- 初版每次调用仍重载权重；RAM状态回灌接口存在不代表已达到实时性能。

准备布局回传后才能生成并核对真实A7TV模型包，再进行openvela板测。
不能把NBG改扩展名当作A7TV，不能把此包称为完整本地ASR或语音全链路镜像。

## Linux上一次执行

保留当前Linux卡，关闭其他NPU程序，确认供电散热，分区至少2GiB空闲。解压进入目录：

```sh
sudo bash test-linux-voice-layout.sh --run --npu-idle-confirmed
```

自动完成encoder/decoder/joiner/vocoder各**一次**固定输入推理；输入取自已通过回传，
每个原始输出必须与以前SHA-256完全一致。临时LD_PRELOAD只观察这个参考进程的
已知A733 ioctl ABI，不修改内核/系统库/厂商文件、命令、时钟、网络或超时参数。
采集pre-submit与post-wait内存快照、ioctl载荷、原生logical地址，并将每个I/O
切片逐字节绑定回已知真实输入输出；缺失/歧义/截断必须报错，不编造VIP地址。

每进程60秒，TERM后5秒KILL，网络内5秒，总调度10分钟。任一可读温度≥75°C
保存并停止；75°C是保守软件测试上限，不是芯片额定温度。不自动reset/重试。
单分配32MiB、单快照128MiB、单模型快照总量512MiB上限；截断会明确失败。
只使用一个NPU参考进程，不是通用/并发LD_PRELOAD追踪工具。四模型依次完成，
错误即停止，失败报告同样保留。

结束只回传 `REPORT:` 对应的压缩包。无需麦克风、说话、联网、API key、安装依赖。

## 输出和边界

- `*-output/outputN.bin`：全部原始输出，必须与上轮golden一致。
- `*-trace/`：私有命令/地址/内存快照，**不要公开上传**。
- `*-trace-manifest.json`：实际采集文件的SHA-256/大小。
- `*-bindings.json`：全部原生输入/输出的分配内切片、VIP地址、快照和对应原字节哈希。
- `layout-summary.json`：只在4模型均通过时生成，仍标记未导出A7TV、未在openvela执行。

参考runner与NuttX `crc32part`都使用reflected CRC32、初值0、最终异或0，
不是zlib的默认CRC。单测加入 `123456789 -> 2dfd2d88` 已知答案防止生产/模拟不一致。
哈希用于本地完整性核验，不是文件真实性签名，也不是恶意NPU命令的安全沙箱。

厂商库、模型及派生prepared数据仅本地私有开发包，不进入Git。ASR NBG/转换工具、
Matcha在A7Z执行、实时麦克风、Agent闭环和openvela语音硬件验收仍未完成。
